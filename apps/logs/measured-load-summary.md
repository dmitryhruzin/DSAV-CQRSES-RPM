# Зведена таблиця виміряних показників під навантаженням (load)

Джерело: `apps/logs/*-load.log` (сирі логи, без retry-strip). Методологія —
як у [analyz-10.md](analyz-10.md): пропускаються перші 10 с навантаження
(якір — `startedAt` першого `http.request`), метрики рахуються на **успішних**
запитах (`success=true`). Час — у мілісекундах.

Стовпці:

- **Error rate** — частка запитів із `success=false` від усіх запитів після
  10-с пропуску (всі класи разом).
- **p95 RT Запити / Створення / Оновлення** — 95-й перцентиль
  `http.request.durationMs` для GET / POST / PATCH відповідно.
- **p95 узгодженості (усі команди)** — 95-й перцентиль
  `max(event.handle.endedAt) − http.request.startedAt`, **об'єднаний пул**
  POST+PATCH (перцентиль рахується на пулі сэмплів, а не усередненням
  покомандних p95).

Складові:

- **Інстанс (USD/год → /міс ×730), eu-central-1:** m7i.large 0,12075 →
  88,15 ; m7a.large 0,13886 → 101,37 ; m7g.large 0,09780 → 71,39.

  3000 baseline IOPS і базова пропускна здатність — включено.
- **Диск io2 (eu-central-1, 1500 provisioned IOPS):** сховище
  100 × 0,138 = 13,80 + IOPS 1500 × 0,072 = 108,00 →
  **диск io2 = 121,80 USD/міс**.

Підсумок по машині = інстанс/міс + диск/міс. Наприклад,
m7a-io2 = 101,37 + 121,80 = **223,17**; m7a-gp3 = 101,37 + 9,52 = **110,89**.

io2 розраховано для **right-sized 1500 provisioned IOPS** (×2 над виміряним
CloudWatch avg-peak; latency io2 sub-ms від кількості IOPS не залежить, тож
ця ціна сумісна з виміряною latency). Тарифи диска eu-central-1 узгоджені з
[index.md (таблиця EBS-дисків)](index.md).

### Спостереження

- **Error rate скрізь ≈ 0** (≤ 0,02 %) — система під навантаженням
  стабільна; залишкові поодинокі помилки не впливають на статистику.
- **Диск gp3 → io2 стабільно прискорює** усі класи на обох варіаціях
  (наприклад, Manual CQRS m7a: p95 узгодженості 14,4 → 10,2 мс). Це підтверджує
  фізичну основу коефіцієнта K.
- **Classical vs Manual:** на m7a-io2 показники близькі (узгодженість 10,16 vs
  10,19 мс), на m7i Classical помітно швидший за Manual (узгодженість
  m7i-gp3: 25,9 vs 34,4 мс) — різниця архітектури обробки подій сильніше
  проявляється на повільнішому інстансі.
- Дрібні розбіжності з [../JMT-prediction-manual/log-analisis-load.md](../JMT-prediction-manual/log-analisis-load.md)
  (напр. PATCH-узгодженість m7i-gp3 34,405 проти 34,350) — бо ця таблиця з
  сирих `apps/logs/` без retry-strip, а log-analisis-load.md — з
  `logs10-noretry/`.
